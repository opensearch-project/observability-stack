The GenAI Observability SDKs ([Python](/docs/send-data/ai-agents/python/), [TypeScript](/docs/send-data/ai-agents/typescript/)) record evaluation results as OpenTelemetry `gen_ai.evaluation.result` log events, one per score, linked to the agent trace that was judged. Three APIs produce them:

| API | Use it for | Result has suite, run, case |
|---|---|---|
| `score()` | **Online**: grade live traffic, inline or from a separate evaluator job | No |
| `evaluate()` | **Offline**: run a synchronous agent over a test suite with scorer functions | Yes |
| `Benchmark` | **Offline**: log cases you ran yourself (async agents, other harnesses, imported results) | Yes |

None of them creates spans: the agent's own spans are the trace, and the results attach to it. Every attribute they set is listed in [Data Model & Ingestion](/docs/agent-evals/data-model/#attributes). The full argument reference is in the SDK guides: [Python](https://github.com/opensearch-project/genai-observability-sdk-py/blob/main/docs/agent-evaluations.md), [TypeScript](https://github.com/opensearch-project/genai-observability-sdk-ts/blob/main/docs/agent-evaluations.md).

Call `register()` first. It sets up the logs exporter that carries the events next to the traces exporter, and its `agent_name` / `agent_version` become `gen_ai.agent.name` / `gen_ai.agent.version` on every result unless a call or the judged span names another agent.

## Online evaluation: `score()`

### Levels

<Tabs syncKey="sdk-lang">
<TabItem label="Python">

```python
from opensearch_genai_observability_sdk_py import Op, observe, score


@observe(name="travel_planner", op=Op.INVOKE_AGENT)
def travel_planner(question: str) -> str:
    answer = "Paris"
    # Span level, inline: the active span is judged.
    score("tool_selection", 1.0, label="pass", evaluator="tool_check", evaluator_type="code")
    return answer


# Span level, later: a stored span by its ids (works after the span ended).
score("relevance", 0.92, trace_id="6ebb9835f43af1552f2cebb9f5165e39", span_id="89829115c2128845",
      evaluator="relevance_judge", evaluator_type="llm_judge")

# Trace level: only the trace id.
score("helpfulness", 4.0, trace_id="6ebb9835f43af1552f2cebb9f5165e39", score_min=1, score_max=5)

# Session level: gen_ai.conversation.id, no trace context.
score("goal_completed", 1.0, label="pass", conversation_id="session-456", evaluator_type="human")
```

</TabItem>
<TabItem label="TypeScript">

```typescript
import { Op, score, withObserve } from "@opensearch-project/genai-observability-sdk-ts";

await withObserve("travel_planner", { op: Op.INVOKE_AGENT }, async () => {
  // Span level, inline: the active span is judged.
  score({ name: "tool_selection", value: 1, label: "pass", evaluator: "tool_check", evaluatorType: "code" });
  return "Paris";
});

// Span level, later: a stored span by its ids.
score({ name: "relevance", value: 0.92, traceId: "6ebb9835f43af1552f2cebb9f5165e39", spanId: "89829115c2128845",
        evaluator: "relevance_judge", evaluatorType: "llm_judge" });

// Trace level.
score({ name: "helpfulness", value: 4, traceId: "6ebb9835f43af1552f2cebb9f5165e39", scoreMin: 1, scoreMax: 5 });

// Session level.
score({ name: "goal_completed", value: 1, label: "pass", conversationId: "session-456", evaluatorType: "human" });
```

</TabItem>
</Tabs>

The level defaults to `span` with a span context, `trace` with only a trace id, and `session` with only a conversation id. Pass `level=` to set it (`span`, `trace`, `session`, `tool_call`).

### Pass rules

The verdict is `gen_ai.evaluation.score.label` = `pass` or `fail`. Your code decides it; Dashboards shows it and never computes one. The same rule applies to `score()`, `evaluate()` and `Benchmark`:

1. The verdict comes from the first source that gives one: a `pass` / `fail` `label` (any case), then `EvalScore.passed`, then `threshold` + `direction` (`maximize` by default).
2. A label that is not a verdict (for example `partially_relevant`) moves to `opensearch.gen_ai.evaluation.judge_label` when the result has a verdict. Without a verdict it stays the label, and the result shows as **Scored**, outside pass rates.
3. A scorer that returns a `bool` returns a verdict.

```python
score("answer_quality", 3.0, threshold=4, score_min=1, score_max=5)   # fail
score("latency_s", 9.2, threshold=12, direction="minimize")            # pass
score("faithfulness", 0.4, label="fail", explanation="Claims a hotel the tool did not return")
score("relevance", 2.0, label="partially_relevant", threshold=4)       # fail, judge_label kept
```

Record the scale with `score_min` / `score_max` (`scoreMin` / `scoreMax`) so a 1 to 5 judge and a 0 to 1 check read side by side, and name the evaluator with `evaluator`, `evaluator_version` and `evaluator_type` (`llm_judge`, `code`, `human`, `external`).

### LLM judges

Record what a judge checked and how, so two judge versions are never mixed up:

| Python `score()` / `@scorer` | TypeScript | Attribute |
|---|---|---|
| `evaluator_description` / `description` | `evaluatorDescription` | `opensearch.gen_ai.evaluation.evaluator.description` |
| `judge_model` | `judgeModel` | `gen_ai.request.model` |
| `judge_prompt_name` | `judgePromptName` | `gen_ai.prompt.name` |
| `judge_prompt_version` | `judgePromptVersion` | `gen_ai.prompt.version` |
| `judge_trace_id` (also on `EvalScore`) | `judgeTraceId` | `opensearch.gen_ai.evaluation.judge.trace_id` |

```python
from opentelemetry import trace

from opensearch_genai_observability_sdk_py import Op, enrich, observe, score

JUDGE_PROMPT = "You grade answers 1 to 5 ... Reply with JSON."


@observe(name="answer_quality_judge", op=Op.CHAT)
def judge(question: str, answer: str) -> dict:
    enrich(model="claude-haiku-4-5", system_instructions=JUDGE_PROMPT)  # the full prompt, on the judge's span
    return call_model(JUDGE_PROMPT, question, answer)  # {"score": 4, "reason": "..."}


with trace.get_tracer("judge").start_as_current_span("judge run") as span:
    verdict = judge(question, answer)
judge_trace_id = format(span.get_span_context().trace_id, "032x")

score(
    "answer_quality", verdict["score"],
    trace_id=agent_trace_id, span_id=agent_span_id,
    explanation=verdict["reason"],
    threshold=4, score_min=1, score_max=5,
    evaluator="answer_quality_judge", evaluator_type="llm_judge",
    evaluator_description="Correct, grounded in tool output, answers the question",
    judge_model="claude-haiku-4-5",
    judge_prompt_name="answer-quality", judge_prompt_version="v3",
    judge_trace_id=judge_trace_id,
)
```

Results identify the prompt by name and version (`answer-quality@v3`). The full prompt never goes on a result event; if you want it, it belongs on the judge's own LLM span as `gen_ai.system_instructions`, as above. See [Judge prompts](/docs/agent-evals/data-model/#judge-prompts).

### Errors

If the evaluator fails, send an error result: `error.type` set, no value, no label. It shows as **Evaluator error** and is left out of pass rates.

```python
score("relevance", trace_id=agent_trace_id, span_id=agent_span_id, error_type="TimeoutError", evaluator="relevance_judge")
```

### An online evaluator job

A typical online evaluator samples recent agent traces, skips the ones it already scored, and posts a result per trace. `OpenSearchTraceRetriever` reads the traces back:

<Tabs syncKey="sdk-lang">
<TabItem label="Python">

```python
import random
from datetime import datetime, timedelta, timezone

from opensearch_genai_observability_sdk_py import OpenSearchTraceRetriever, register, score

register(service_name="my-agent-evaluator")
retriever = OpenSearchTraceRetriever(host="https://localhost:9200", auth=("admin", PASSWORD), verify_certs=False)

since = datetime.now(timezone.utc) - timedelta(minutes=60)
roots = retriever.list_root_spans(services=["my-agent"], since=since, max_results=50)
done = retriever.find_evaluated_trace_ids([r.trace_id for r in roots])

for root in roots:
    if root.trace_id in done or random.random() > 0.5:  # skip scored traces, sample 50%
        continue
    question = root.input_messages[0].content if root.input_messages else ""
    answer = root.output_messages[-1].content if root.output_messages else ""
    verdict = judge(question, answer)
    score("answer_quality", verdict["score"], trace_id=root.trace_id, span_id=root.span_id,
          explanation=verdict["reason"], threshold=4, score_min=1, score_max=5,
          evaluator="answer_quality_judge", evaluator_type="llm_judge",
          agent_name=root.agent_name)
```

</TabItem>
<TabItem label="TypeScript">

```typescript
import { OpenSearchTraceRetriever, register, score } from "@opensearch-project/genai-observability-sdk-ts";

const provider = await register({ serviceName: "my-agent-evaluator" });
const retriever = new OpenSearchTraceRetriever({
  host: "https://localhost:9200",
  auth: { username: "admin", password: process.env.OPENSEARCH_PASSWORD! },
  verifyCerts: false, // local self-signed certificate only
});

const since = new Date(Date.now() - 60 * 60 * 1000);
const roots = await retriever.listRootSpans({ services: ["my-agent"], since, maxResults: 50 });
const done = await retriever.findEvaluatedTraceIds(roots.map((r) => r.traceId));

for (const root of roots) {
  if (done.has(root.traceId) || Math.random() > 0.5) continue;
  const verdict = await judge(root.inputMessages[0]?.content ?? "", root.outputMessages.at(-1)?.content ?? "");
  score({ name: "answer_quality", value: verdict.score, traceId: root.traceId, spanId: root.spanId,
          explanation: verdict.reason, threshold: 4, scoreMin: 1, scoreMax: 5,
          evaluator: "answer_quality_judge", evaluatorType: "llm_judge", agentName: root.agentName });
}
await provider.forceFlush();
```

</TabItem>
</Tabs>

Run it on a schedule. `find_evaluated_trace_ids()` makes it safe to re-run. The stack's eval canary (`docker-compose/agent-eval-canary/`) is a working example with deterministic checks.

## Offline evaluation: `evaluate()`

`evaluate()` runs your task once per case. Each call is its own trace, like production: the SDK adds no wrapper span, stamps `test.suite.name`, `test.suite.run.id` and `test.case.id` on the root span the task starts, and parents each scorer's result to that span.

<Tabs syncKey="sdk-lang">
<TabItem label="Python">

```python
import sys

from opensearch_genai_observability_sdk_py import EvalScore, Op, evaluate, observe, register, scorer

register(service_name="travel-agent", agent_name="travel_planner", agent_version="v3")


@observe(name="travel_planner", op=Op.INVOKE_AGENT)
def travel_planner(question: str) -> str:
    return "Paris" if "France" in question else "I do not know"


@scorer(name="exact_match", evaluator_type="code")
def exact_match(input, output, expected) -> bool:
    return output == expected


@scorer(name="answer_quality", threshold=4, score_min=1, score_max=5, evaluator_type="llm_judge",
        judge_model="claude-haiku-4-5", judge_prompt_name="answer-quality", judge_prompt_version="v3")
def quality(input, output, expected) -> EvalScore:
    verdict = judge(input, output)
    return EvalScore(name="answer_quality", value=verdict["score"], explanation=verdict["reason"])


result = evaluate(
    name="travel-capitals",  # test.suite.name
    task=travel_planner,
    data=[
        {"case_id": "fr", "case_name": "France", "input": "Capital of France?", "expected": "Paris"},
        {"case_id": "pe", "case_name": "Peru", "input": "Capital of Peru?", "expected": "Lima"},
    ],
    scores=[exact_match, quality],
    run_name="v3 shorter prompt",
    run_description="Shorter system prompt, same model",
)
sys.exit(1 if result.summary.fail_count or result.summary.error_count else 0)
```

</TabItem>
<TabItem label="TypeScript">

```typescript
import { Op, defineScorer, evaluate, observe } from "@opensearch-project/genai-observability-sdk-ts";

const travelPlanner = observe({ name: "travel_planner", op: Op.INVOKE_AGENT }, (question: string) =>
  question.includes("France") ? "Paris" : "I do not know",
);

const exactMatch = defineScorer({ name: "exact_match", evaluatorType: "code" }, (_i, output, expected) => output === expected);

const result = evaluate({
  name: "travel-capitals",
  task: (input) => travelPlanner(String(input)), // synchronous; use Benchmark for async agents
  data: [
    { caseId: "fr", caseName: "France", input: "Capital of France?", expected: "Paris" },
    { caseId: "pe", caseName: "Peru", input: "Capital of Peru?", expected: "Lima" },
  ],
  scores: [exactMatch],
  runName: "v3 shorter prompt",
});
process.exitCode = result.summary.failCount || result.summary.errorCount ? 1 : 0;
```

</TabItem>
</Tabs>

- A scorer receives `(input, output, expected)` and returns a `bool` (a verdict), a number, an `EvalScore`, or a list of `EvalScore`. Scorers are synchronous; wrap an async judge yourself, or use `Benchmark`.
- `@scorer(...)` (`defineScorer()`) declares the evaluation name, `threshold`, `direction`, `score_min`, `score_max`, `evaluator`, `evaluator_type`, the description and the judge context. Fields set on a returned `EvalScore` win.
- A task that raises is not scored: each scorer emits an error result with `error.type` set to the exception class. A scorer that raises emits one error result. The run continues.
- `evaluate()` prints a summary and returns it (`result.summary`: run id, pass, fail and error counts, and per-evaluation `avg`, `min`, `max`, `count`). The summary is computed locally and is not sent.

## Offline evaluation: `Benchmark`

Use `Benchmark` when you run the cases yourself: async agents (all TypeScript agents, Python `asyncio`), another test harness, or results you import. Pass the agent run's `trace_id` and `span_id` so each result links to its trace.

<Tabs syncKey="sdk-lang">
<TabItem label="Python">

```python
from opensearch_genai_observability_sdk_py import Benchmark, EvalScore

b = Benchmark(name="travel-capitals", run_name="v3 async", agent_name="travel_planner", agent_version="v3")
for case in cases:
    answer, trace_id, span_id = run_agent(case["input"])  # your harness: run (or await) the agent
    b.log(
        case_id=case["case_id"], case_name=case["case_name"],
        input=case["input"], output=answer, expected=case["expected"],
        trace_id=trace_id, span_id=span_id,
        scores=[EvalScore(name="exact_match", value=float(answer == case["expected"]), threshold=1)],
    )
summary = b.close()
```

</TabItem>
<TabItem label="TypeScript">

```typescript
import { Benchmark } from "@opensearch-project/genai-observability-sdk-ts";

const bench = new Benchmark("travel-capitals", { runName: "v3 async", agentName: "travel_planner", agentVersion: "v3" });
for (const c of cases) {
  const { answer, traceId, spanId } = await ask(c.input); // withObserve returns span.spanContext() ids
  bench.log({
    caseId: c.caseId, caseName: c.caseName, input: c.input, output: answer, expected: c.expected,
    traceId, spanId,
    scores: [{ name: "exact_match", value: answer === c.expected ? 1 : 0, threshold: 1 }],
  });
}
const summary = bench.close();
await provider.forceFlush();
```

</TabItem>
</Tabs>

`scores` is a list of `EvalScore` or a `{name: value}` map. `log(error_type="TimeoutError", ...)` sends every listed score as an error result.

## Cases, expected output and runs

- **Case ids.** Pass a stable `case_id` (`caseId`). Without one the SDK uses the first 16 hex characters of the SHA-256 of the input, so editing the input makes a new case. See [Case identity](/docs/agent-evals/data-model/#case-identity).
- **Expected output.** A case's `expected` is sent on each of its results as `opensearch.test.case.expected`: strings as is, other values JSON-encoded, cut at 32768 characters with `opensearch.test.case.expected_truncated` = `true`. Pass `record_expected=False` (`recordExpected: false`) if your test data is sensitive; scorers still get it. Inputs and outputs are never sent on results: they are in the agent's trace.
- **Run name and description.** `run_name` and `run_description` (`runName`, `runDescription`) are shown in place of the generated run id (`run_<timestamp>_<random>`) and explain what changed.
- **Run id.** `run_id` (`runId`) sets `test.suite.run.id` exactly. Use it to [shard a suite](/docs/agent-evals/ci/#shard-a-suite-under-one-run-id) under one run, or to add re-scored results to an existing run.
- **Metadata.** `metadata=` is copied to every result of the run. Reserved keys (`test.*`, `cicd.pipeline.*`, the evaluation fields) are dropped with a warning.
- **CI.** Inside GitHub Actions, GitLab CI and Jenkins the SDK adds `cicd.pipeline.*`. See [Run evaluations in CI](/docs/agent-evals/ci/#cicd-attributes).

## `OpenSearchTraceRetriever`

Reads stored agent traces back from OpenSearch, for evaluator jobs and trace-based scorers. Python needs the `[opensearch]` extra (`pip install "opensearch-genai-observability-sdk-py[opensearch]"`).

| Method (Python / TypeScript) | Returns |
|---|---|
| `list_root_spans(services=, since=, max_results=)` / `listRootSpans({...})` | One `SpanRecord` per recent trace: the root span with its agent name, messages and token counts |
| `get_traces(identifier)` / `getTraces(id)` | A `SessionRecord`: all traces of a conversation id (`gen_ai.conversation.id`) or of one trace id, with their spans |
| `find_evaluated_trace_ids(trace_ids)` / `findEvaluatedTraceIds(ids)` | The ids that already have a `gen_ai.evaluation.result` |

`SpanRecord` carries `trace_id`, `span_id`, `parent_span_id`, `operation_name`, `agent_name`, `model`, `input_messages`, `output_messages`, `tool_name`, `tool_call_arguments`, `tool_call_result`, `input_tokens`, `output_tokens` and the raw document. For Amazon OpenSearch Service, pass a SigV4 `auth` (Python: `RequestsAWSV4SignerAuth`).

Spans are exported in batches and ingested a few seconds later. In a trace-based scorer, call `force_flush()` on the provider first and poll until the span count is stable.
